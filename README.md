# Ворс — выездная химчистка мягкой мебели (MVP-шаблон)

Клиент открывает ссылку, выбирает мебель на 3D-сцене, видит примерную цену и отправляет заявку с фото.
Владелец в кабинете видит состав, фото и контакты, согласует цену и время, а клиент видит обновление
по своей приватной ссылке. Шаблон рассчитан на одну компанию — один экземпляр и одна база.

**Стек:** Next.js 16 (App Router) · React 19 · TypeScript · three.js 0.187 + React Three Fiber 9 + Drei 10 ·
Motion · PostgreSQL (`pg`) · sharp · Zod. Node.js ≥ 20.9 (проверено на 24 LTS).

---

## Быстрый старт (локально)

```bash
npm install
cp .env.example .env.local        # при необходимости поправьте значения
npm run db:local                  # локальный PostgreSQL без Docker (оставьте терминал открытым)
npm run db:migrate                # в другом терминале: схема БД
npm run dev                       # http://localhost:3000
```

- Кабинет: http://localhost:3000/admin — пароль из `OWNER_INITIAL_PASSWORD` (только при первом запуске,
  потом смените его в «Доступ»).
- Демо-заявки (вымышленные): `SEED_PASSWORD=<пароль> npm run db:seed` при запущенном сервере.
- Проверки: `npm run typecheck`, `npm test` (формула), `E2E_PASSWORD=<пароль> npm run e2e`
  (58 сквозных проверок по HTTP; для повторных локальных прогонов добавьте
  `E2E_DATABASE_URL=$DATABASE_URL`, чтобы сбросить счётчики лимитов).
- Отладка 3D: `/?3d=off` — постер как без WebGL, `/?3d=fail` — экран ошибки загрузки с повтором.

## Публикация

Пошагово для Vercel + Neon — [docs/DEPLOY.md](docs/DEPLOY.md).

Подходит любая платформа с Node.js (Vercel, Timeweb Cloud Apps, Yandex Cloud Serverless Containers,
VPS с `npm run build && npm start`) и любой PostgreSQL 15+ в **UTF-8** (Neon, Supabase, Yandex Managed PostgreSQL…).

1. Создайте БД и выполните `DATABASE_URL=... npm run db:migrate` (или схема применится сама при первом запросе).
2. Переменные окружения:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения к PostgreSQL (обязательно) |
| `DATABASE_SSL=1` | если провайдер требует SSL |
| `APP_URL` | публичный адрес без слеша — метаданные, sitemap, проверка Origin |
| `OWNER_INITIAL_PASSWORD` | первый пароль владельца, ≥ 10 символов; после первой смены не используется |

3. Заявки и фото хранятся только в PostgreSQL — локальных файлов нет, поэтому serverless-хостинг подходит.
4. После деплоя: войдите в кабинет → смените пароль → заполните «Компания» (контакты, город) → «Тарифы».

> В этой поставке приложение **не развёрнуто**: доступов к хостингу и БД в рабочей среде не было.
> Для публикации нужен аккаунт хостинга и управляемого PostgreSQL (см. «Регулярные расходы»).

### Правила расчёта

1. База — цена варианта из прайса.
2. Надбавки **складываются** и берутся от базы: `цена_за_шт = база × (100 + загрязнения% + вторая_сторона%) / 100`.
3. Цена за штуку округляется до 10 ₽, затем умножается на количество.
4. Минимальный заказ относится только к чистке: `чистка = max(сумма, минимум)`.
5. Выезд за город — фиксированная доплата **после** минимума.
6. Позиции «Другое» — «По фото»: итог не показывается, выводится «не меньше X ₽» и число позиций с ручной оценкой.
7. Сервер пересчитывает всё сам; присланные браузером суммы игнорируются. В заявке сохраняются прайс и расчёт на момент отправки.

### Данные и безопасность

- Приватная ссылка клиента `/z/<токен>`: 24 случайных байта. По номеру заявку открыть нельзя.
- Публичный API заявки не отдаёт телефон, заметку владельца и идентификаторы фото.
- Фото: реальный формат проверяет sharp (JPEG/PNG/WebP), минимум 200×200, до 12 МБ; сервер поворачивает фото по EXIF,
  ужимает до 1600 px и перекодирует в WebP (метаданные и геолокация удаляются). Фото отдаются только владельцу с сеансом.
- Повтор отправки с тем же ключом идемпотентности возвращает ту же заявку, а не дубль; при гонке спасает UNIQUE.
- Изменяющие запросы проверяют Origin; лимиты: 12 заявок в час, 40 загрузок в час и 8 попыток входа за 15 минут с одного IP.
- Сеанс владельца хранится в cookie HttpOnly и SameSite=Lax на 14 дней. Смена пароля закрывает все прежние сеансы.
- Service worker кеширует только статику и офлайн-экран; `/api`, `/admin`, `/z`, `/checkout` не кешируются.
