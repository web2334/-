# Ограничения MVP и статус проверок

## Что проверено (22.11.2026, локально, macOS arm64, Node 24.22.3, PostgreSQL 18 embedded)

- `tsc --noEmit` — без ошибок; `next build` — успешно.
- `vitest`: 7 тестов формулы (округление, сложение процентов, количество, минимум, выезд, смешанный заказ, вторая сторона только у матраса).
- `scripts/e2e.mjs` против **продакшен-сборки** (`next start`): **58/58**. Сценарий: клиент отправил заявку →
  владелец вошёл, открыл её и согласовал цену и время → клиент увидел обновление. Также проверены: фото (настоящий
  формат, подделка, размер, доступ), идемпотентность, 409 при изменении после отправки, «Другое» без фото,
  время без даты, снимок прайса, минимум и выезд, закрытые маршруты, Origin, HttpOnly, смена пароля закрывает
  сеансы, бонус-код один на заявку, лимит частоты, удаление вместе с фото.
- Во встроенном браузере (эмуляция 375×812 и десктоп 1280, светлая и тёмная темы): все 9 моделей, взмах и
  реплика, смена категорий, подгонка камеры, корзина с объединением одинаковых позиций, удаление с отменой,
  восстановление черновика после перезагрузки, загрузка фото, сетевой сбой с повтором без дубля,
  постер без WebGL (`?3d=off`), ошибка 3D с повтором (`?3d=fail`), мини-игра (стирание пятен реальными жестами).

## Что НЕ проверено

- **Реальный телефон** — устройство было недоступно; проверялась только эмуляция мобильной ширины.
- **Service worker / офлайн-экран** — встроенная панель браузера отказалась регистрировать SW
  («unknown error when fetching the script»), хотя `/sw.js` отдаётся корректно. Проверьте в Chrome:
  DevTools → Application → Service Workers, затем режим Offline.
- **Опубликованный экземпляр** — деплой не выполнялся (нет доступов к хостингу и БД).
- Safari/iOS и Firefox — не запускались.

## Ограничения продукта

- **Figma-файл не создан**: в рабочей среде не было Figma MCP. Для макетов подключите Figma MCP и попросите собрать экраны
  (главная, оформление, заявка, кабинет) — либо снимайте экраны с работающего сайта.
- **.blend не создан**: Blender не был установлен и недоступен через MCP. Модели созданы процедурно
  (`scripts/build-models.mjs`); `.blend` собирается одной командой — `scripts/blender/import_models.py` (см. ADAPTATION.md).
- Разные размеры дивана, кресла и матраса — **разные модели**. Варианты стула («сиденье» и «со спинкой»)
  показываются одной моделью, и на сцене это подписано.
- Модель «Другое» — пример (пуф), а не изображение предмета клиента.
- Онлайн-оплаты нет. Дата и время — пожелание; мастер подтверждает их по телефону.
- Бонус за игру выдаётся без защиты от накрутки: клиент может отправить «100 %» запросом. Это осознанно:
  код один на заявку и применяется владельцем вручную после проверки. Автоматического погашения нет.
- Уведомлений о новых заявках нет: владелец видит их в кабинете (список обновляется раз в минуту и по кнопке).
- Одна учётная запись владельца; ролей нет. Восстановления пароля по почте нет — сброс через БД
  (`DELETE FROM owner_account;` и новый `OWNER_INITIAL_PASSWORD`).
- Лимиты запросов считаются по IP из `X-Forwarded-For`; за прокси без этого заголовка все клиенты делят один лимит.
- Фото хранятся в PostgreSQL (bytea) — просто и подходит для serverless, но при большом объёме лучше S3.
- Брошенные загрузки фото (без заявки) удаляются через сутки при следующих загрузках, а не по расписанию.
- Политика обработки данных — шаблон; её нужно проверить с юристом и указать реквизиты оператора.
- PostgreSQL должен быть в UTF-8, иначе поиск по кириллице в кабинете будет чувствителен к регистру.
